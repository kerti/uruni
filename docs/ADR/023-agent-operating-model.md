# ADR-023 — Agent operating model: one orchestrator, pinned role agents

**Status:** Accepted · implemented — change only by adding a superseding ADR · [ADR index](./README.md)

**Context.** Uruni is built by a solo maintainer working through AI agents, and until now `CLAUDE.md` said what an agent may *do* without saying what an agent *is*. In practice one session did everything: reading the whole repo to answer a small question, thinking hard about a mechanical rename, thinking lightly about the ledger. That wastes the expensive thing (context in the main window) on the cheap work, and starves the work that deserves depth.

The knobs that fix this are not prose. Model and effort are set by `.claude/agents/*.md` frontmatter (`model`, `effort` — `low`…`max`) and by session settings; an instruction in `CLAUDE.md` asking an agent to "use maximum effort" changes nothing, because the orchestrator has no such parameter to pass. Whatever we decide has to land in configuration or it is decoration. Meanwhile [ADR-020](./020-dev-environment.md) already settled *how* agent config lives here: committed, portable, `${CLAUDE_PROJECT_DIR}`-addressed. This decision extends that; it does not amend it (ADR-020's "three hooks" remains the record of what M1 shipped — there are now four).

**Decision.**

- **The main session is the orchestrator: Opus at `medium` effort**, pinned by `model` and `effortLevel` in `.claude/settings.json`. It plans, dispatches, verifies diffs, writes PR bodies, and asks for commits. It does not do bulk work a role agent can do more cheaply.
- **Six role agents in `.claude/agents/`**, each pinning its own model and effort: `researcher` (sonnet · medium, read-only), `planner` (sonnet · xhigh), `grill` (sonnet · max), `builder` (sonnet · medium), `builder-deep` (sonnet · high), `reviewer` (sonnet · high, read-only). Frontmatter effort overrides the session level, which is the only reason `max` is reachable at all — `effortLevel` in a settings file does not accept it.
- **`xhigh`, not `max`, is the planning default.** `max` is documented as prone to overthinking with diminishing returns; on high-volume, low-ambiguity work — filing issues, writing docs — it buys latency and spend rather than quality. `max` is reserved for `grill`, where overthinking is the assignment.
- **Delegation is approval-gated.** A fourth hook, `.claude/hooks/agent-gate.sh`, matches `PreToolUse(Agent)` and returns `permissionDecision: "ask"` for every subagent call, built-ins included. Cost control the maintainer can see beats a policy an agent is asked to remember.
- **Delegation is a context optimization, not a token optimization**, and `CLAUDE.md` says so. A subagent re-derives the repo cold and misses the prompt cache, so total spend rises; what it buys is a main window clean enough to keep judgment intact. Below roughly three files or two tool calls, inline wins.
- **The sign-off surface is never delegated:** commits, pushes, PR creation/labelling/merge, tags, `Decisions.md`, dropping an ADR's `draft` tag, and scope calls against `PRD.md §4`.
- **Blocking commands yes, polling no.** Agents run `make check`/`test`/`web-test`/`build` and wait. `make e2e`, `make stack-*`, foreground servers, `--watch` modes and CI queries are the maintainer's — this generalizes the existing never-watch-CI rule to every long-running interactive thing, since the failure mode (an agent burning tokens to learn something a human would have told it) is identical.

**Consequences.** `CLAUDE.md` is now loaded into every custom subagent's context, so its length is paid on each launch — the new section is deliberately compressed, and the file's growth is a real cost now rather than a stylistic one. The pinned `model`/`effortLevel` apply to anyone who clones the repo and are a default, not enforcement: `/effort`, `--effort`, and above all `CLAUDE_CODE_EFFORT_LEVEL` override them, the last one silently. Role agents inherit the session's permissions but not its conversation, which makes the brief-writing rules in `CLAUDE.md` load-bearing rather than advisory. Tools without a subagent mechanism (Codex, Cursor, Zed via the `AGENTS.md` symlink) get the phases and the prohibitions but not the pinning; there, effort is the human's dial. And the agent gate adds a prompt to a workflow that previously had none — accepted deliberately, because an ungated `Agent` call is the one action in this repo that can spend a lot of money without touching a file.
